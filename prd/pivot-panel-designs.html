Search is how you build the batch

A configured instance lists only the enrichment modules it has enabled, so every provider in the pivot panel is one that works — and a well-equipped instance still puts dozens of them against a single IP address. This is one panel combining a filter box with a run tray. Neither is new on its own; together they do something neither can, which is let you assemble a run out of several searches.

Rule 01

Selection outlives the filter

Clearing the search box must never empty the tray. If it did, searching would destroy what you had picked, and assembling a run out of two searches would be impossible — which is the only reason to put these two together at all.

So the selection is state on the panel, not on the visible list.

Rule 02

Select-all means select matching

The button names the number it will actually add, and that number is always scoped to the search. This is where the speed comes from: two typed words and one click add four providers. An unscoped “select all” in a fifty-row list is a way to fire fifty requests by accident.

Rule 03

The count reveals what it is hiding

Once a selection outlives the filter you can have six picked and two on screen, which is the footgun the first two rules create. The tray says how many are out of sight, and clicking it shows exactly those — the same control, no new surface.

Keyboard

Typing never leaves the keyboard

Space cannot toggle a row while you are typing — it types a space — so the rule is positional: arrow down moves into the list, and the gestures change with it. Enter belongs to the tray the moment anything is picked, so the primary action is always the one on screen.

What this replaces, and what it costs

The panel today is a flat list of cards with no way to search it and no way to run more than one provider. Running several is possible only through a meta-pivot whose narrowing control is a fifty-checkbox list 1061px tall — taller than the panel it sits in, and it buries every other provider nearly three screens down.

goneThe meta-pivot and its facet. Enrich (all applicable) exists only because there was no way to run several providers at once. When the list is the selection, it has no job left — and the 1061px facet goes with it.
movedThe cap. maxCandidates was judged against a count no such provider can supply. On the tray it guards the thing that is actually worth guarding: how many requests one click fires.
costRunning one provider is no longer a bare row click. Clicking a row picks it, because mis-picking is free and mis-running spends a request. Running one is the labelled button on the row, on hover or focus. This is the real trade, and the single-provider case is still the common one — worth watching once it is in front of analysts.
cutGrouping, and the availability split. Grouping was built and dropped: the catalogue does not partition — 46 of 50 IP providers share one input family, 32 are called Lookup, 44 vendor folders hold 40 singletons. The ready-versus-unconfigured split was dropped for a better reason: a configured host never lists a module it cannot run, so there is nothing to split.
