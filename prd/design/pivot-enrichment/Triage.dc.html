C5 The rejected count is a button. Clicking it reveals the suppressed rows in place, so "previously rejected are suppressed" is inspectable rather than a claim — and it is the only way back from a mis-rejection, since the memory is per-session and per-pivot (D14).
C6 A rejected row is struck in place, not moved. Moving it re-orders the table under the analyst's cursor mid-triage. It also loses its checkbox entirely — an unchecked box would read as mere deselection, and rejection is a deliberate act with memory.
D23 "Skipped", never "removed". A deduped candidate is already on the canvas and its data was deliberately left untouched. Nothing was lost, so the word must not suggest it was.
D5 Regex lives here and only here. These filters are client-side over data already in hand. Narrowing, which is server-bound, has no regex widget at all.
