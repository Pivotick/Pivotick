Origin-less pivots — the quiet second door

Search, import and staging pivots run with no selection at all (D19), so they cannot sit in a list keyed to one. Proposal: they need no new surface. Pivot mode has an origin, and an empty origin is a legitimate state — so origin-less pivots are simply the ones that apply when the origin is empty, and are folded into a collapsed group when it is not. One registry, one pipeline, one triage pane, exactly as D19 argued.

C14 No mainheader pill, no second menu, no new surface. The first draft of this decision gave origin-less pivots a mainheader entry, which handed a secondary door the most prominent chrome in the app. Pivot mode dissolves the problem instead: the mode already has an origin, an empty origin is meaningful, and D19's argument — the gap was never "the data came from elsewhere", it was "there is no node to run this on" — is answered by the mode's own vocabulary.
